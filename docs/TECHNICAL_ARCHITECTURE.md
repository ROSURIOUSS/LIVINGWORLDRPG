# TECHNICAL ARCHITECTURE

Статус: **DESIGNED / PROPOSED** (см. ADR). Ничего из описанного ниже, кроме шаблонных классов UE, пока не реализовано.

## 1. Слои
1. **Planetary Model** — данные планеты (сфера, тектоника-lite, климатические пояса, океаны, континенты). Хранится как сеточная модель на сфере (ADR-0005), не как UE-уровень.
2. **Global Simulation (L3)** — агрегированно: демография, экономика, политика, войны, миграции по регионам/государствам. Шаг: игровые недели–месяцы.
3. **Regional Simulation (L2)** — индивидуальные NPC в загруженной области без детальной физики/навигации. Шаг: игровые часы–дни.
4. **Local/Active Simulation (L1)** — NPC возле игрока: навигация, анимация, физика, диалоги. Шаг: кадр/тик.
5. **Presentation** — UE: World Partition, HLOD, Mass-представление толпы, UI. Только то, что рядом с игроком.

Сущность переходит между L1/L2/L3 без потери идентичности (один `FLWId`; детализация «подгружается» из компактного состояния + сида).

## 2. Ядро (pure C++, без UObject)
- `FLWId` — 64-бит: [type:8 | shard/region:16 | counter:40]. Выдаётся только менеджером ID, детерминированно.
- `FLWRng` — PCG; сид `(WorldSeed, SystemId, EntityId, Tick)`.
- `FLWTime` — игровое время как int64 тиков (1 тик = 1 игровая минута базово); календарь планеты настраивается; симуляция = планировщик событий + периодические системы с собственным шагом.
- **Event bus** — типизированные события (`FLWEvent{Type, Tick, Cause[], Actors[], Payload}`); причинные цепочки хранятся (поле `Cause`), история строится из них. Системы общаются событиями и read-only запросами, не прямыми ссылками.
- **Command queue** — все изменения мира — команды, применяемые детерминированно в конце шага. Через неё же исполняются предложения AETHER после валидации.
- Хранение: SoA-таблицы по типам сущностей, ID вместо указателей, пространственный индекс (грид/кватернарное дерево по регионам).

## 3. Модули (предложение; создаются по мере необходимости, не пустыми)
```
LWCore          (ID, RNG, Time, Events, Commands, Save primitives)      ← ни от чего проектного
LWWorldData     (планета, регионы, биомы, ресурсы; данные+генераторы)   ← LWCore
LWSim           (Population, NPC, Society, Economy, Politics, History,   ← LWCore, LWWorldData
                 Ecology, Info) — подсистемы внутри одного модуля до тех
                 пор, пока границы не устоятся
LWSave          (форматирование, версии, миграции, целостность)          ← LWCore
LWAether        (контракты, очередь, провайдеры, валидатор)              ← LWCore, LWSim(интерфейсы)
LWGame          (UE-слой: GameMode, Player, Mass-представление, UI)      ← всё выше (UE module = текущий LIVINGWORLDRPG)
LWTests         (Automation/Headless)                                    ← всё
```
Правило: зависимости только вниз; Presentation никогда не владеет состоянием симуляции. Дробление `LWSim` на отдельные модули — только когда замер времени сборки/связанности это оправдает (ADR-0003).

## 4. NPC
Структура `FLWNpc` (компактная): id, раса/геном-ссылка, возраст (тики рождения), пол, черты (OCEAN-подобный вектор + темперамент), навыки (разреженные), потребности (голод, жажда, сон, безопасность, социальное…), цели (стек), профессия, жильё, семья (ссылки на id), инвентарь-ссылка.
- **Память**: кольцевой буфер краткосрочной + индексированная долговременная; запись `{event, importance, valence, tick, source, certainty, related[]}`; забывание — затухание по importance; допускаются ошибочные/ложные записи через certainty и источник.
- **Решения**: utility AI + расписания (L2), StateTree/Behavior (L1); AETHER — только для редких «значимых» решений (§AETHER).

## 5. Историческая симуляция и рождение игрока
Зерно: 100 первоначальных людей в нескольких регионах (геном, возраст, потребности). Симуляция шагами (L2/L3): поиск пищи → пары → дети → стоянки → поселения → … Состояние пишется снапшотами каждые N лет (для перехода «мир доводится до момента»). Момент рождения игрока выбирается по настраиваемому распределению (учёт числа подходящих семей, состояния государств), затем подбирается семья; родословная и геном берутся из реальной симуляции (не генерируются заново).

## 6. Знание vs истина
Объективный мир (`WorldState`) и `KnowledgeBase` каждого агента (включая игрока) — раздельные хранилища. Информационная единица `{Claim, Source, Born, Transmitted, Area, Certainty, Distortions[]}` распространяется по социальному графу/маршрутам со скоростью, зависящей от инфраструктуры. UI и диалоги читают только KnowledgeBase.

## 7. Сохранения
Бинарный чанковый формат: заголовок (версия формата, версия генератора, seed, настройки, хэши), чанки по регионам/типам, CRC на чанк, запись во временный файл + атомарный rename, ротация бэкапов (N последних). Хранится: seed, версии, события истории, сущности, ресурсы, знания, состояние игрока, время, состояние AETHER (очередь/кэш по необходимости). Не хранится: производные данные (меш ландшафта, навигация) — восстанавливаются из seed и данных. Миграции — цепочка `vN→vN+1`.
Offline progression: агрегированный шаг L3 с обязательной материализацией «значимых» событий (смерти правителей, войны), чтобы не терять причинность.

## 8. Интеграция с UE 5.8
- **World Partition** для L1-области; планета целиком в UE не грузится.
- **Mass** (MassEntity/MassGameplay/MassAI/ZoneGraph/SmartObjects доступны в движке, в проекте пока не включены) — кандидат для L1-толпы; решение через прототип и замер (ADR-0004).
- **Async**: `UE::Tasks` для L2/L3 шагов; результаты применяются командами на game thread.
- **Навигация**: Navmesh/ZoneGraph только в L1.
- Проверено: плагины Mass* присутствуют в `D:/Game/UE_5.8/Engine/Plugins`. НЕ проверено: производительность и API-стабильность Mass в 5.8 — требуется исследование.

## 9. Мультиплеер (будущее)
Совместимость заложена: серверно-авторитетное ядро, ID, командная модель, события. Не реализуется в v1.
