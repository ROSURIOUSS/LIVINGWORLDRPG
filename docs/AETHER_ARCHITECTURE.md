# AETHER ARCHITECTURE

Статус: **DESIGNED / PROPOSED** (ADR-0006, 0007). Код отсутствует.

Решения пользователя (утверждены в мастер-промпте): размещение Hybrid, общение NPC Hybrid, приоритет World, режим «автономный, но контролируемый».

## Принципы
1. AETHER — подсистема-советник: читает снимок контекста, возвращает `FAetherProposal`. Никогда не пишет в состояние мира.
2. Мир работает при `AETHER=Off` и без сети (детерминированные эвристики — «Tier 0» — всегда доступны).
3. Любое предложение проходит конвейер валидации ядра и только потом превращается в команду.
4. Все вызовы бюджетируются и логируются.

## Уровни вычислений
| Tier | Что | Где | Когда |
|---|---|---|---|
| 0 | Правила, utility AI, статистические модели | ядро, всегда | каждый шаг |
| 1 | Лёгкие обучаемые/локальные модели (опционально) | локально, async | периодически |
| 2 | Локальная LLM (опционально) | процесс-сайдкар | редкие значимые решения, диалоги |
| 3 | Внешняя LLM по API | провайдер | только по явному включению пользователем, с лимитами |

## Компоненты (из ТЗ → реализация)
World Intelligence (тренды, конфликты, прогноз) · NPC Intelligence (значимые решения, диалоги) · Society Intelligence (групповые процессы) · Narrative Intelligence (выявление интересных ситуаций; не придумывает сюжет) · Memory Intelligence (суммаризация/забывание/индексация) · Decision Intelligence (варианты + оценка последствий). Каждый — модуль внутри `LWAether`, реализующий `IAetherAdvisor`; включается/отключается отдельно.

## Конвейер решения
`Trigger(event/периодический) → ContextBuilder (ограниченный снимок, только знания агента) → Queue(priority, deadline, budget) → Provider(Tier0..3) → Proposal → RuleValidator → ResourceCheck → ConsequenceEstimate → CommandQueue → Result logged`
Если валидация отклоняет — предложение отбрасывается и записывается причина; ядро не «подстраивается» под LLM.

## Контроль нагрузки
Приоритеты, пакетирование, кэш по хэшу контекста, периодические обновления вместо покадровых, событийные триггеры, жёсткие лимиты: запросов/мин, токенов/игровой час, $/игровой час. Один NPC ≠ один запрос: значимость решения определяет доступ к Tier 2/3.

## Диалоги (AI_DIALOGUE)
Гибрид: структурированные намерения и факты из KnowledgeBase NPC → шаблонный/грамматический генератор (Tier 0) → опциональная LLM-«обёртка» стиля. LLM не добавляет фактов, которых нет в знаниях NPC (проверка пост-фактум по списку допустимых утверждений).

## Безопасность и секреты
Ключи API — только в переменных окружения/локальном конфиге вне git. Нет отправки персональных данных пользователя.

## Тесты
Replay: журнал предложений+ответов воспроизводится в детерминированном режиме (LLM-ответы мокаются/читаются из журнала) → тот же хэш состояния. Тест `AETHER=Off` на полной симуляции.

## Открыто
Выбор локальной модели/рантайма (NNE vs sidecar llama.cpp-подобный), формат контекста, оценка стоимости. Требует исследования и замеров — ADR-0007.
